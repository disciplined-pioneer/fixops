# Sales Report Generator (с намеренным багом)

Небольшое приложение на Python, генерирующее отчёт по продажам.
Специально содержит **технический баг в коде** (не ошибку бизнес-логики):
при обработке данных гарантированно вылетает `IndexError`, и полный
traceback записывается в `logs/app.log`.

## Запуск

```bash
python3 main.py
```

После запуска смотрите `logs/app.log` — там будет INFO-лог по шагам
работы и один ERROR-лог с полным traceback.

## Структура

- `main.py` — точка входа, настройка логирования (файл + консоль)
- `report_generator.py` — логика отчёта (здесь и находится баг)
- `data/sales_data.json` — тестовые данные

## В чём баг (спойлер)

В `report_generator.py`, функция `calculate_growth`, строка с
`next_day = days[i + 1]`. Цикл идёт по всем дням `range(len(days))`,
но на последней итерации `i + 1` выходит за пределы списка —
классическая ошибка "на единицу" (off-by-one). Расчёты для всех
предыдущих дней корректны, ошибка выявляется только на последнем шаге.

## Зачем это нужно

Проект удобен для:
- тестирования систем сбора/мониторинга логов (Sentry, ELK, Grafana Loki и т.п.)
- тренировки навыка чтения traceback'ов и поиска бага по логам
- демонстрации разницы между "ошибкой в логике" (неверный результат)
  и "ошибкой в коде" (падение с исключением)
